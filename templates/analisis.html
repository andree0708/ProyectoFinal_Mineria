Contexto

Un dataset balanceado, de tweets cortos y etiquetas automáticas

Sentiment140 tiene {{ d.n_tweets|miles }} tweets de {{ d.n_usuarios|miles }} usuarios, exactamente la mitad positivos y la mitad negativos. Esto hace que la accuracy sea una métrica justa: un clasificador al azar acertaría el 50 %. Los tweets son cortos (≈{{ d.palabras_media.negativo|round|int }} palabras), lo que deja poco contexto a cada modelo.

Las etiquetas no son manuales: se asignaron por los emoticonos :) y :(, que luego se quitaron del texto (supervisión distante). Ese ruido en las etiquetas limita la accuracy alcanzable con modelos clásicos a un rango de 75–80 %.

El tiempo en este dataset no refleja la opinión real

Los tweets cubren del {{ d.fecha_min }} al {{ d.fecha_max }}, pero solo hay datos en {{ d.n_dias_con_datos }} de {{ d.n_dias_rango }} días. Además, hasta el {{ st.corte }} la proporción de positivos ronda el {{ st.pct_positivo_antes|pct(0) }}, y a partir de esa fecha es {{ st.pct_positivo_despues|pct(0) }}: todos los tweets son negativos.

Un cambio tan brusco no es un cambio de opinión pública, sino el resultado de cómo se recolectaron los datos. Cualquier análisis temporal sobre Sentiment140 debe advertirlo, o mostrará un desplome de sentimiento que no existió.

Random Forest rinde menos y tiende a decir «positivo»

Random Forest queda {{ '%.1f'|format((M[best].accuracy - rf.accuracy) * 100) }} puntos por debajo de {{ best }}, y la diferencia es significativa. Además está sesgado: predice positivo en el {{ rf.pct_pred_positivo|pct(0) }} de los casos, cuando el test tiene 50 %. Marca como positivos al {{ rf.fpr|pct(0) }} de los tweets negativos, frente al {{ M[best].fpr|pct(0) }} de {{ best }}.

Una explicación probable: cada árbol, con profundidad limitada, solo usa unas pocas de las 5 000 columnas TF-IDF, y los tweets negativos que no contienen esas palabras clave terminan en hojas «positivo». Para esta tarea, los modelos lineales son más precisos y mucho más ligeros.

Las negaciones se pierden y eso cuesta precisión

La lista de stop words en inglés de scikit-learn elimina {% for w in ng.stop_words_negacion_eliminadas %}{{ w }}{{ ', ' if not loop.last }}{% endfor %}, y la limpieza parte las contracciones (don't → don). Así, "not good" se convierte en "good".

El {{ ng.pct_tweets_con_negacion|pct(0) }} de los tweets contiene una negación. En ellos, {{ ng.modelo }} acierta {{ ng.accuracy_con|pct }}, frente al {{ ng.accuracy_sin|pct }} en el resto: una caída de {{ '%.1f'|format((ng.accuracy_sin - ng.accuracy_con) * 100) }} puntos, estadísticamente significativa. Conservar las negaciones es la mejora más directa para el pipeline.

Pero el error medio por marca es de {{ '%.0f'|format(mb.mae * 100) }} puntos, porque cada marca tiene pocos tweets. Sirve para comparar y ordenar marcas, no para dar un porcentaje exacto.

Conclusión

Qué recomendamos

Usar {{ best }} (o SVM, estadísticamente equivalentes) con TF-IDF: ≈{{ M[best].accuracy|pct(0) }} de accuracy en datos ruidosos y ≈{{ a.manual.modelos[best].accuracy|pct(0) if a.manual else '—' }} en datos etiquetados a mano, entrenan en segundos y ocupan poco. Random Forest no compensa su costo.

Limitaciones

  • Etiquetas por emoticonos (ruido) y sin clase neutral
  • Solo inglés, tweets de 2009
  • Recolección temporal sesgada: no inferir tendencias del dataset
  • Las negaciones se eliminan en el preprocesamiento
